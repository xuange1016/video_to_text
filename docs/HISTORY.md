# 这些版本是怎么进仓库的

片语最初在本机持续开发，未逐次建立 Git 提交。本仓库于 **2026-11-06** 集中整理 1.0.0 → 1.4.0 的真实里程碑。

- 保留 GitHub 仓库原有的 MIT 许可证初始提交。
- 每版使用实际保存的源码补丁与对应打包界面恢复，按版本顺序提交、推送和打标签。
- Git 提交使用整理当天的真实时间，没有修改作者日期来伪装开发历史。
- README、CHANGELOG、VERSION、忽略规则、第三方声明与发布辅助文件在整理时补充；它们的出现不表示历史开发阶段已经具备这些文档。

## 怎么确认源码没有串台

恢复的 Python 源码重新编译后，与原始 `Pianyu.exe` 内对应的 Python 代码对象逐个比较。只归一化编译文件路径；应用逻辑字节码全部一致。QML / SVG 则与原始打包目录逐文件比对。

| 版本 | 应用模块字节码 | 界面资源 | 本轮恢复源码测试 |
| --- | --- | --- | ---: |
| 1.0.0 | 全部匹配 | 匹配 | 10 / 10 |
| 1.1.0 | 全部匹配 | 匹配 | 15 / 15 |
| 1.2.0 | 全部匹配 | 匹配 | 18 / 18 |
| 1.3.0 | 全部匹配 | 匹配 | 34 / 34 |
| 1.4.0 | 全部匹配 | 匹配 | 36 / 36 |

可公开的源文件 / UI / 原始程序 SHA256 与比对结果见 [source-verification.json](history/source-verification.json)。其中构建脚本等 SHA256 对应恢复时的原始快照；最新版本为发布整理调整过构建辅助文件，应用 Python 与 UI 保持对应里程碑内容。

测试通过只覆盖对应场景，完整网络获取仍受平台实时可用性影响；本机打包版检查与干净系统验收的区别见 [ACCEPTANCE.md](../ACCEPTANCE.md)。

## Release 里的安装包

每版安装包来自对应的冻结 `Pianyu` 打包目录。公开分发前统一补入第三方版权 / 许可正文，并去除应用没有使用的 GPL-only Qt 附加模块和运行日志，之后由 Inno Setup 重新封装。**各版应用 EXE、Python 逻辑和 QML 界面保持原版。**

因此公开安装包的 SHA256 与早期仅在本机生成的安装包不同。这是本次分发补正，校验请以对应 Release 内的 `SHA256SUMS.txt` 为准；它与源码证明中的原始程序 EXE SHA256 是不同的文件。

历史版本适合查看演进与回归问题，日常使用建议下载 [最新版本](https://github.com/xuange1016/video_to_text/releases/latest)。所有版本共用同一用户数据位置，旧程序未保证能完整理解新版本的任务类型，请勿直接用旧版操作自己的日常任务库。开发隔离方法见 [DEVELOPMENT.md](DEVELOPMENT.md)。
